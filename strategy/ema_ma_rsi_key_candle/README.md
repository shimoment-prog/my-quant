# EMA / MA / RSI 关键 K 棒策略

Pine Script v6 回测脚本：`ema_ma_rsi_key_candle.pine`。适用图表示例为币安 ETHUSDT USDT 永续、普通 5 分钟 K 线。脚本使用当前图表的数据，不连接交易账户、不提交真实订单。

## 已确认规则

- 橙线：SMA10，简单移动平均线；白线：EMA10。沿用用户设置，不按照“快线/慢线”的称呼交换类型。
- RSI 默认 `ta.rsi(close, 14)`。5 分钟图上的 14 表示 14 根 5 分钟 K 线，非 14 天。
- RSI 区间包含边界：多单 50～70，空单 30～50。
- 多单关键 K：阳线，且最低价严格高于两线，整个下影线也必须在两线上方。
- 空单关键 K：阴线，且最高价严格低于两线，整个上影线也必须在两线下方。
- 线值按关键 K 收盘时计算；“整根 K 在均线外”是用本根 high/low 比较本根收盘确认后的均线值，不是逐笔回放 K 线内的均线轨迹。
- 开仓参考价为关键 K 收盘价，`process_orders_on_close = true`。
- 多单和空单的止损均为关键 K 当时的橙线价格，开仓后固定；空单止损在入场价上方。
- 多单止盈 = 入场参考价 + 1.5 ×（入场参考价 − 止损）。
- 空单止盈 = 入场参考价 − 1.5 ×（止损 − 入场参考价）。
- 止损、止盈按最小价格跳动单位取整，盈亏比会有很小的取整差异。风险距离不足一个价格跳动、止盈取整后未落在盈利一侧、或空单目标价不为正时不下单。

## 两种触发方式

### 方式一：双均线交叉

- 多：橙线由下向上穿过白线，开始等待第一根多单关键 K。
- 空：橙线由上向下穿过白线，开始等待第一根空单关键 K。
- 允许交叉当根直接成为关键 K，这是用户明确确认的规则。

### 方式二：回踩／反弹白线

- 多：橙线仍在白线上方，出现阴线且收盘价低于白线；从下一根开始等待第一根多单关键 K。
- 空：橙线仍在白线下方，出现阳线且收盘价高于白线；从下一根开始等待第一根空单关键 K。
- 触发条件只要求该根收盘位于白线相应一侧，不额外要求收盘价刚刚穿过白线。

### 首版等待与持仓约定

用户确认了方式一允许当根关键 K，其余等待细节采用此前提出的首版解释：

- 等待不限根数，直到第一根合格关键 K、均线方向失效或离开允许开仓时间范围。
- 反向交叉取消原方向等待；两线相等时也取消，后续重新触发。
- 方式二要求均线排列与交易方向一致，不在相反排列下提前等待。
- 同方向的方式二重复触发，不重置第一次触发的时间。
- 两种方式同时满足只下单一次，交易注释优先标记为方式一。
- 每次提交开仓指令后清空所有等待状态；持仓期间不保留新的待开仓信号。图上的关键 K 三角是指令提交标记，不代表模拟撮合器必然接受并成交；实际成交以策略测试器交易清单为准。
- 同时只持有一笔仓位，不加仓、不直接反手；原仓平仓的同一根 K 不重新开仓，从下一根起接受新触发。
- 均线交叉、RSI 退出区间都不直接平仓，平仓只由固定止盈／止损决定。
- 输入的时间范围仅限制新开仓；结束时间之后，已有仓位仍等待原止盈／止损，不强制按最后一根收盘平仓。末尾未平仓交易不计入已平仓胜率。

## 回测设置与查看

1. 在 TradingView 选择 Binance 的 ETHUSDT 永续合约，而非同名现货；设为普通 5 分钟 K 线。
2. 在 Pine 编辑器新建策略，粘贴 `.pine` 文件全文并添加到图表。
3. 在“输入”调整指标参数、开仓起止时间，分别启用或停用两种下单方式；在“属性”调整资金、仓位、手续费和滑点。
4. 在策略测试器／策略报告查看胜率、净收益、最大回撤和交易清单。图表右上角也显示基于 `strategy.closedtrades` 和 `strategy.wintrades` 的胜率。
5. 图上圆点表示开始等待，三角形表示关键 K；蓝线是入场参考价，红线是固定止损，绿线是固定止盈。独立 RSI 曲线可以另加官方 RSI14；脚本把 RSI 数值放在数据窗口，避免与价格共用纵轴。

默认资金 10,000 USD、每次使用权益的 10%、100% 保证金（无杠杆），手续费单边 0.05%、滑点 0。这些是可调整的回测占位设置，不代表币安账户的实际费率、保证金设置或已确认的仓位规则。单边费用会在进出场分别收取。

USD 在这里用于回测账户记账，作为 USDT 的近似，不模拟 USD/USDT 汇率差异。将初始资金、仓位比例调得太小，或保证金不足时，模拟订单可能无法成交。参数切换、图表周期变化或历史数据加载范围变化后，须重新查看实际覆盖区间和交易清单。

仅计算胜率时也应配置交易成本；固定 1:1.5 的价格风险回报比不是扣除成本后的净盈亏比。未计成本且每笔都精确按 1.5R 盈利或 1R 亏损时，理论盈亏平衡胜率为 40%，加入成本、跳空或滑点后门槛会提高。

## 复制代码与版本／缩进报错

若出现 `The Pine version of this script is unspecified`，说明编辑器未识别 Pine 版本声明，会回退到 Pine v1；这也可能连带产生缩进报错。

1. 打开 `.pine` 文件，复制全文，包含第一行 `//@version=6`。
2. 在 TradingView 的 Pine 编辑器代码区全选并替换原代码，不要在默认脚本后追加。
3. 确认第一行恰好是 `//@version=6`，使用半角字符，行首无空格；不要复制 Markdown 的反引号围栏、标题或行号。如仍报版本未指定，可删除第一行并手动重输。
4. 第二行 `strategy(...)` 必须从行首开始。当前文件已把声明写成单行，减少复制多行参数时的缩进问题。
5. 保留后续 `if`／`else` 代码块内的缩进，不能把全文所有行都顶格。
6. 保存并重新添加到图表。如仍有错误，记录第一条错误的行号和该行代码，再定位修复。

本地文件确认版本声明存在、无 BOM 或行首缩进；未读取用户编辑器中的粘贴内容，不能据此确定其版本声明为何未被识别。

### 替换后仍按 Pine v1 编译

若继续出现 `Script could not be translated from: ... var bool ...`，同时仍提示版本未指定，应先单独排查版本声明的识别，不要删除策略中的 `var` 或改变交易规则。

1. 新建一个单独的空白脚本，清空默认内容。手动输入第一行 `//@version=6`，不要从聊天消息复制这一行。
2. 在下一行粘贴下面三行，保存并添加到图表：

```pine
indicator("Pine v6 check", overlay = true)
var bool versionCheck = false
plot(close)
```

完整的最小测试文件为 `pine_version_check.pine`。成功时应出现收盘价线，且不再提示按 Pine v1 编译。它只验证该脚本的版本声明和基本语法解析，不是完整策略编译或回测验证。

测试成功后，保留手动输入的版本声明，删除下面三行测试代码，将正式策略从 `strategy(...)` 开始的全部正文粘贴到第二行，再保存并添加。仍有报错时，请提供正在编译的 Pine 编辑器实际第 1～10 行代码和报错行号，检查是否正在保存／编译预期的脚本标签。

## 撮合与验证边界

- 策略仅在 K 线收盘计算，不使用多周期未来数据，也不使用背离的回填拐点。
- 新仓和对应止盈／止损在同一次计算中提交；不依赖下根 K 收盘才补挂退出单。
- 不启用 `calc_on_order_fills`，避免用历史 K 线的完整价格信息反复计算收盘前的交易。
- 模拟收盘成交不能保证实盘在同一价格成交。修改滑点后，止盈／止损仍以信号收盘价计算，实际模拟成交的盈亏比会偏离 1:1.5。
- 后续同根 K 同时触及止盈止损时，由 TradingView 模拟撮合路径决定先后；可在套餐和历史数据支持时开启 Bar Magnifier（柱线放大器）细化。不能默认每次都是止盈先发生。
- 普通 Pine 回测不自动完整计入永续资金费率，也不复刻币安分档维持保证金与真实强平机制。
- 验证记录见 `VALIDATION.md`。未实际在 TradingView 编译或回测时，不应把本地逻辑检查描述为平台回测结果。
