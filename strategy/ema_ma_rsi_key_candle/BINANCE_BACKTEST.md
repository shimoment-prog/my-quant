# 币安历史数据回测

将当前 Pine 的指标和交易规则改写为 Python，下载币安 USD-M 永续 ETHUSDT 历史 K 线，在本地逐根回放，输出胜率、净收益、收盘权益回撤和逐笔交易。只需 Python 3.9 或更新版本，使用标准库，无需安装第三方包，也无需币安 API Key。

## 本次数据和设置

用户选择最近三个完整月。以 2026-11-18 为基准，取 UTC 2026 年 8、9、10 月。

- 数据源：币安官方 `data.binance.vision/data/futures/um/monthly/klines/ETHUSDT/5m/`，非现货数据。
- 下载范围：UTC `[2026-07-28, 2026-11-01)`，27,648 根连续 5 分钟 K 线，含开仓前约 4 天预热。
- 开仓按收盘时刻筛选：`2026-08-01 00:00 <= time_close <= 2026-11-01 00:00`，与 Pine 的时间条件一致。Binance 的 `close_time_ms + 1` 才是这个计划收盘时刻。因此起始时刻前一根 K 的收盘信号也在边界内。
- 4 份月 ZIP 的官方 SHA256 校验全部通过；规范化 CSV 的 SHA256 为 `639beb73e0e7163013db53ba82e49887d476e8bb8460d05d70b75d934ab2f52a`，来源与校验记录在 CSV 旁的 `.metadata.json`。
- 橙线 SMA10，白线 EMA10，RSI14；两种进场方式和两个方向均开启，固定橙线止损，目标 1.5R。其余等待约定沿用 README 首版说明。
- 初始 10,000 USDT，每笔名义仓位为当时权益的 10%，无杠杆。该比例不是单笔止损风险比例。
- 费用基准：单边 0.05%，零滑点，作为可调整假设，不代表用户账户实际费率。
- tick=0.01 USDT，数量步长=0.001 ETH，作为本次参数；未追溯验证历史交易规则变更。

基准组累计手续费约 574.53 USDT，成本影响远大于两种 OHLC 顺序假设的差别。243 笔交易的价格盈亏为正，但其中 81 笔触发止盈后仍不足以覆盖双边手续费，按净盈亏统计为亏损。因此扣费后胜率为 162/592，而非 243/592。

无费率组的每笔仓位随权益变化，不能直接用其 51.54 减去另一组的手续费来逐笔对账。基准组的自身 gross、fee、net 已分别核对。

数据已下载时直接回测即可：

```bash
python3 backtest.py \
  --csv data/ETHUSDT-5m-20260728-20261101.csv \
  --start 2026-08-01 --end 2026-11-01 \
  --interval 5m --fee-percent 0.05 --slippage-ticks 0 \
  --intrabar stop-first \
  --output-dir results/20260801-20261101-stop-first
```

下载日期按 K 线开盘时刻的 `[start,end)`；回测开仓日期按收盘时刻的 `[start,end]`。更换回测起点时，应提前下载预热数据；本次预热超过 1,000 根，减少 EMA 初始值的影响。

每次运行输出：

| 文件 | 用途 |
| --- | --- |
| `report.md` | 阅读回测结果与设置 |
| `summary.json` | 完整参数、汇总、数据 hash、来源和限制 |
| `trades.csv` | 逐笔参考价、实际模拟成交价、固定止盈止损、费用和净盈亏 |
| `equity.csv` | 每根收盘时的权益、浮盈亏和回撤 |

若要对比其他设置，在上面的命令中更换参数并使用不同 `--output-dir`：

- `--method cross`：只运行方式一；`--method pullback`：只运行方式二。
- `--direction long` 或 `--direction short`：只做一个方向。
- `--fee-percent` 填账户实际的单边百分比，例如 `0.05` 表示 0.05%，不是 5%。当前只有统一费率，没有区分 maker/taker。
- `--slippage-ticks 1`：入场市价与止损成交增加 1 tick 不利滑点；限价止盈不加这个滑点。
- `--intrabar tv-path`：按开盘距高、低点的距离决定先到哪个极值；等距约定低点先到。它是 OHLC 路径近似，不是 TradingView 的逐笔对齐证明。

## 怎样验证回测没有算错

1. 检查数据旁的元数据，确认是 futures/um、ETHUSDT、5m，四个月官方 SHA256 均通过。
2. 打开 `trades.csv`，对照 `entry_time_utc` 找到刚结束的关键 K：对应开盘时刻是入场时刻减 5 分钟；不能错对到下一根 K。
3. 多单检查 low 严格高于两线、阳线、RSI 50～70；空单检查 high 严格低于两线、阴线、RSI 30～50，并核对均线触发／回踩等待。
4. 止损对照信号时 SMA，止盈对照 1.5R，并考虑 tick 半入取整。入场后的止损和止盈均保持不变。
5. 检查净盈亏等于方向价格盈亏减两侧费用；期末未平仓不计入胜率。
6. 重点查看 `both_levels_touched=True` 的交易。本次有 20 根退出 K 同时覆盖止盈与止损，5 分钟 OHLC 无法确认真实先后；两种路径结果已分别运行。

## 结果边界

- 这是 Python 独立 OHLC 回测，Pine 尚未在 TradingView 官方编译器完成验证，两者也尚未逐笔对齐。
- `stop-first` 对双触 K 保守地先止损；`tv-path` 使用明确的极值路径假设。需要更细周期或逐笔数据才能缩小顺序不确定性。
- 收盘入场不会回溯入场 K 此前的高低点。止损跳空按开盘价加不利滑点，止盈跳空可按更优开盘价成交。
- 没有逐笔成交时间的退出，只给出所在 K 的开盘／收盘区间，不伪造精确退出时刻。
- 最大回撤仅统计 K 线收盘权益，不能当作盘中最大回撤。
- 未计永续资金费率，未复刻标记价格触发、分档保证金和真实强平；这些结果并非完整实盘交易成本。
- 没有设置结束时强制平仓。已有持仓可随额外提供的后续数据继续退出；数据结尾仍未平仓则单列浮盈亏，胜率只统计已平仓。
- EMA 从下载的第一个 close 开始递推，RSI 使用 Wilder RMA。全平价格的零分母边界明确约定为 RSI=100。足够预热会降低种子差异，但不承诺所有边界与 TradingView 内部实现完全一致。
