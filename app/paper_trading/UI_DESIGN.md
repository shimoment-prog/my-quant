# 实时模拟交易网页交互设计建议

记录日期：2026-11-27。本文用于需求讨论与后续界面实现。

用户已确认多任务独立资金、两种策略部署方式、按任务切换独立面板。
用户随后确认按本方案实施；本文保留设计时的建议措辞，首版落地范围见 [README.md](README.md)。指标编辑器先提供EMA/SMA/RSI，其余常用指标逐步增加。
业务范围及确认状态以 [REQUIREMENTS.md](REQUIREMENTS.md) 为准。

## 1. 页面骨架

建议采用左侧导航、右侧单任务工作区，避免同时显示多个任务的数据。

```text
左侧导航                   右侧：当前选中的任务
┌──────────────────┐      ┌─────────────────────────────────────────┐
│ 新建模拟任务      │      │ 任务名 / 策略版本 / 币种 / 周期 / 状态   │
│ 任务列表          │      │ 启动、暂停开仓、恢复、结束等操作         │
│   A：ETH · 4h     │      ├─────────┬─────────┬─────────┬───────────┤
│   B：BTC · 1h     │      │ 当前权益│ 账户余额│ 已实现净│ 浮动盈亏 │
│   C：SOL · 30m    │      │         │         │ 盈亏    │           │
│                  │      ├─────────────────────────────────────────┤
│ 策略库            │      │ K线主图 + EMA / SMA + 交易标记 / 仓位框 │
│   手动策略        │      │ RSI等副图，与主图时间轴对齐             │
│   代码策略        │      ├─────────────────────────────────────────┤
│                  │      │ 交易明细 | 账户 | 规则与配置 | 日志      │
└──────────────────┘      └─────────────────────────────────────────┘
```

左侧任务项建议显示名称、币种、周期、策略摘要和运行状态，可搜索或按状态筛选。
任务未选中时显示简短引导；新建后进入该任务详情，避免默认混合所有账户结果。
切换任务时，图表、指标、交易选择、账单、账户和日志一起切换。
同币种同周期的不同任务也只显示各自的交易与账户数据。

## 2. 任务工作区

顶部四项账户指标建议为当前权益、账户余额、已实现净盈亏、浮动盈亏。
鼠标悬停可查看口径；初始本金、保证金占用、可用资金和费用在账户页展开。
余额、权益和浮动盈亏应能对账，图上浮盈不得重复计入余额。
标题栏同时显示行情连接状态、最后更新时间和页面时区，断线状态保持可见。

K线主图建议提供缩放、拖动、十字光标、时间定位及最新行情跟随。
主图叠加当前任务实际使用的价格指标，副图展示RSI等指标及参考线。
当前代码策略沿用橙色EMA、白色SMA；显示值必须与策略计算使用值一致。
未收盘K与已确认K应可辨认；改变图表显示设置不应悄悄修改策略规则。
多空仓位框展示实际开仓、初始止损、目标或激活价，并标注实际平仓点。
有移动止损的策略还应展示止损变更，不能用最终止损覆盖整段历史。
信号K、信号参考价与实际模拟成交时间/价格分别展示，避免误认成交时点。
点击仓位框打开交易详情；点击交易行定位K线，定位后保留当前任务上下文。

下方标签页建议如下：

| 标签 | 主要内容 |
| --- | --- |
| 交易明细 | 持仓中及已平仓交易、开平仓价、止盈止损、费用、净盈亏、余额 |
| 账户 | 本金、余额、权益、保证金、费用、胜率、收益曲线及回撤口径 |
| 规则与配置 | 策略版本、参数快照、信号条件说明、任务资金与成本设置 |
| 日志 | 行情连接、信号、模拟订单、拒单原因、恢复及人工操作记录 |

交易详情建议展示各项入场条件、当时指标值和退出原因，便于逐单复核。
“持仓中”不标为Win或Loss；已平仓交易按扣除已计费用后的净额判断结果。

## 3. 创建模拟任务：四步表单

1. **选择策略**：从策略库选手动策略或代码策略，查看版本与交易规则摘要。
2. **选择币种与周期**：选择币安合约、运行K线周期并设置任务名称。
3. **设置资金与成本**：填写独立本金、仓位方式、每笔金额、杠杆、手续费等。
4. **核对并启动**：集中展示完整配置、模拟成交口径及初始账户信息。

策略开放的指标参数与阈值在第一步展示；资金参数集中在第三步，避免混杂。
每笔金额明确标注是“保证金”还是“名义金额”，同步显示杠杆后的名义仓位。
金额、数量、币种精度及参数范围错误在对应字段提示，启动前集中复核。
末步分别提供“保存草稿”和“启动模拟”；草稿只保存配置，不订阅后即自动交易。
真实应用中的启动操作需创建运行记录、固定配置快照并进入可见的启动状态。
界面原型中的上述按钮仅演示交互；示例数据不表示已接入行情或交易后台。

## 4. 策略定义与任务配置

策略库保存可复用的指标、条件、动作、公开参数及策略版本。
模拟任务引用策略版本，绑定币种、周期、独立资金配置和本次运行快照。
一个策略可以建立多个任务，分别比较币种、周期或参数；各任务资金独立。
复制任务建议复制规则和设置，建立新账户，不复制旧余额、持仓及交易历史。
运行记录保存当时策略与参数，后续编辑不改写历史条件或历史成交。
运行中修改规则的具体生效方式仍按需求确认，界面应显式说明生效范围。

## 5. 手动策略编辑器建议

采用普通表单，建议顺序为“指标 → 做多条件 → 做空条件 → 退出规则 → 核对”。
第一批必含EMA、SMA、RSI；OHLC和成交量作为可引用的基础数据。
MACD、布林带（BB）和ATR可逐步补充，具体上线范围仍需确认。
每个指标展示名称、周期、价格来源和显示位置，并给出易读的参数摘要。

条件行采用“左值—关系—右值”：

| 项目 | 建议支持内容 |
| --- | --- |
| 左右值 | OHLC、成交量、已添加指标的输出值、手动数值 |
| 比较关系 | 大于、小于、大于等于、小于等于（`>`、`<`、`>=`、`<=`） |
| 事件关系 | 上穿、下穿；使用相邻已确认K的对应值判断 |
| 区间关系 | 位于区间内，界面明确上下界是否包含 |
| 组内组合 | 全部满足（AND）或任意满足（OR），第一版建议仅单层 |

不要求用户输入公式、画连线或创建嵌套条件组。
建议提供阳线、阴线、整根K在指定线之上/之下的快捷条件。
整根在上方用最低价比较，整根在下方用最高价比较，影线也包含在内。
快捷条件明确触线是否合格；严格高于/低于与包含相等不得混用。
默认建议收盘确认，编辑器在条件旁显示该时点，避免盘中数值反复触发。
退出规则表单按支持能力展示止损来源、止盈方式和参数，并生成可读规则摘要。
保存前提供“如果……则开多/开空；……则退出”的文字预览，便于检查。

## 6. 代码策略与复杂规则

连续同向、交叉后等待关键K、状态取消和分阶段EMA退出交由代码策略承接。
代码策略从 `strategy/` 通过适配器接入，向网页提供规则说明和可配置参数。
代码策略与手动策略共用任务创建、模拟成交、账户、图表及逐笔审计界面。
当前同向交叉关键K策略仍使用代码模板，不以“同根均线交叉＋RSI”简化代替。
其交叉触发、后续关键K等待、取消条件及四种退出须保留已确认的完整语义。
网页只展示该代码策略开放的参数，不承诺表单可表达全部复杂状态逻辑。

## 7. 外部参考及引用边界

- [FreqUI官方文档](https://www.freqtrade.io/en/stable/freq-ui/)：已说明交易视图、机器人状态总览、多个机器人切换及可切换的图表配置，可借鉴“总览选择对象后进入交易视图”的组织方式。
- [QuantConnect实时交易结果文档](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/results)：已说明实时更新的权益曲线、持仓、订单、交易、日志及统计，可借鉴“图表＋统计＋明细分区”的结果展示方式。

这些来源用于说明已存在的交互模式；本文四步表单、独立任务布局和手动规则编辑器是本项目建议，并非上述产品原样提供的功能。
