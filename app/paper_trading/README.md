# 实时模拟交易

本地网页应用，目录为 `app/paper_trading/`。使用币安公开 USDT 永续行情；不需要账户密钥，不调用账户或下单接口。

## 启动

要求 macOS/Linux、Python 3.9+。首次安装：

```sh
cd app/paper_trading
./setup.sh
./start.sh
```

打开 <http://127.0.0.1:8088>。本次已创建 `.venv` 并安装依赖，直接运行 `./start.sh` 即可。macOS也可双击 `start.command`。

后台需要持续运行；关闭浏览器不影响任务，关闭终端或电脑休眠会中断。终端按 Ctrl+C 安全保存并退出。当前服务只监听本机，不对外开放。需要换端口或独立数据目录时：

```sh
./start.sh --port 8089 --runtime /path/to/separate-runtime
```

同一个数据目录只能启动一个进程。运行数据在 `runtime/paper.sqlite3`；备份时先退出后台，再备份整个 `runtime/`。`.venv/`、数据库、缓存和字节码不提交Git。

## 使用流程

1. 点“新建”：选择代码策略或已保存的手动策略。
2. 设置币种、K线周期和任务名称。
3. 设置独立本金、每笔保证金或名义金额、杠杆、单边费率及不利滑点。
4. 核对后选择“保存草稿”或“保存并启动模拟”。

首屏没有预先启动的交易任务。10000U、200U、10倍、单边0.05%只是可编辑表单默认值，不代表已选定验证组合。任务间资金、状态、交易、图表、日志及导出独立；复制任务创建新账户，不复制已有成交和持仓。

任务面板显示K线和真实策略指标、多空仓位框、交易标记、逐笔交易、权益曲线及统计。点击交易行定位对应图表，展开可查看信号条件和指标数值；可导出包含持仓中的 CSV。时间显示为北京时间，保存时间为UTC毫秒。K线标签是开盘时间，信号时间和模拟成交时间分别记录。

## 两种策略来源

### 网页手动策略

在“策略库 → 创建简单策略”中配置 EMA、SMA、RSI 的周期及OHLC价格来源。首版支持：

- OHLCV或指标与数值/另一指标的大于、小于、大于等于、小于等于、上穿、下穿、区间比较。
- 阳线、阴线及整根K含影线严格在线上方/下方。
- 做多/做空开仓，以及可选的多单/空单条件平仓；每组单层“全部满足/任意满足”。
- 固定百分比或信号K EMA/SMA价格止损，以及固定盈亏比止盈。

所有手动条件在同一根确认收盘K上计算，不提供斜率、公式、连线和嵌套状态。多空条件同时成立时优先做多，审计记录 `both_sides_matched`；建议配置互斥条件。每任务同时只持一笔，不加仓、不直接反手，平仓所在K不再入场。

手动策略保存新版本，正在运行的任务仍使用原版本和参数快照。运行后的规则或资金调整通过“复制配置”建立新任务，草稿可以直接编辑。

### 代码策略

已接入 `strategy/ema_ma_rsi_key_candle_same_direction` 版本1.0.0：固定橙色EMA10、白色SMA10、Wilder RSI14，开放同向根数N=3～10以及四种退出（`rr15`、`trail_ema`、`ema_slow`、`ema_turn`）。

保留连续N+1次严格双线同向变化、交叉后下一根起等待首根关键K、完整影线和RSI边界、关键K EMA初始止损及四种独立退出逻辑。关键K不额外要求双线继续同向。不同K线周期均按该周期的K棒计算，历史研究表现并不自动迁移到其他周期。

归档回测代码保持独立。实时适配器在 `backend/engine.py`；将来接入复杂代码策略时，在这里实现统一的收盘/报价状态接口，并在 `backend/service.py` 注册策略名称、版本、开放参数与说明。用增量/归档公式一致性、状态边界及报价成交测试验证后，它即可共用任务、账户和图表。

## 实时行情与成交口径

- 使用真实币安历史K预热，至少200根；实际先加载约600根以支持较长指标。仅完整K推进策略，当前未完成K实时显示盘中指标，不提前触发收盘信号。
- 盘中SMA、EMA、RSI以当前K最新价格作为暂定收盘价，从上一根已确认指标状态重新试算。SMA10使用前9根收盘价加当前价；EMA10使用上一根EMA与当前价按2/11权重更新；Wilder RSI14使用本根暂定涨跌更新平均涨跌。每次更新都回到确认状态，不把每笔成交当作新K线。
- 图中未收盘指标标为“盘中”，随当前K变化；收盘后同一时点的最终值替换预览并只提交一次。预览不会修改信号、止损、账户或指标递推状态；缺少紧邻上一根确认K时不生成预览。行情源、周期、价格来源及参数一致时采用相同的指标口径，REST轮询仍可能产生数秒显示差异。
- 优先使用公开WebSocket `aggTrade`＋K线。收盘信号产生后挂起模拟订单，之后收到且时间不早于确认信号的价格事件才成交，分别保存信号价与实际模拟价。
- 固定止盈按目标价成交（不奖励越过目标的更优报价），止损按实际收到的触发价加不利滑点；报价跳过止损/目标时，尚未开仓的订单可能拒绝。价格/数量按该币合约限制取整。
- 盘中真实价格检查止损、止盈和1.5R激活。EMA追踪在确认收盘后更新，对后续报价生效；EMA变缓/转向退出收盘确认后，等待后续报价平仓。
- 数量以保证金×杠杆或配置的名义金额计算，盈亏不再次乘杠杆。开平仓分别收手续费。未平仓权益＝余额＋浮盈亏；尚未发生的平仓费不预扣；Win/Loss只根据闭单净收益判断。
- 当前未模拟资金费、标记价触发、维持保证金和强平，也未模拟深度冲击、部分成交。它用于策略前向验证，不是币安撮合器的完整复制。
- 最大回撤按实际观测报价权益统计，与归档回测的K收盘权益回撤口径不同。权益图保留最近10000个采样点；最大回撤和全部账单继续累计。K图默认加载最近1500根，更早的确认K及当时指标保存在数据库，可继续加载和定位历史交易。指标递推状态持续保存，不随窗口重新播种。

### 当前网络下的REST备用通道

2026-11-27实测此电脑WebSocket可握手但未收到有效实帧。程序10秒未收到首条有效数据后，自动切为**真实聚合成交 `aggTrades` 轮询**（至少5秒，按公开接口限流调整），并在任务连接提示中写明来源；本次已经收到实际成交及K线数据。

备用通道按真实连续成交ID处理，使用真实成交价格而不是K线高低价伪造触价。至少5秒加网络请求/限流等待的延迟会影响信号收到与成交时点，不能当作毫秒级实时执行。每次新连接/缺口恢复只建立最新游标，断线旧价不回填订单；成交ID缺失或积压过大时明确标记缺口并重新同步。

同币种同周期任务共享行情订阅，但账户完全独立。所有行情客户端共用1800权重/滚动60秒的保守预算，429按Retry-After共享冷却并记录缺口。不同币种/周期增加时，备用通道会等待请求预算，轮询延迟相应增大。遇到限流或网络错误会显示连接异常并按上限重试，不能将数据不连续的结果当作完整样本。

## 暂停、结束和恢复

- “暂停开新仓”：取消尚未成交的入场及等待状态，已有持仓继续退出管理。
- “恢复开新仓”：行情正常时重新等待新信号，不执行暂停期间的旧信号。
- “结束任务”：停止新单，已有持仓按原规则退出后结束。
- “平仓并结束”：等下一有效实时报价模拟平仓后结束，不伪造当前即时成交。
- “删除任务”：无持仓、无待成交开仓的草稿或已结束任务显示此按钮。确认后永久删除该任务的账户、交易、图表数据和日志，不影响其他任务和策略库；如需留存，请先导出CSV。运行中、暂停中或仍在等待平仓的任务需先结束，不能直接删除。
- 断线时暂缓新开仓并自动重连；补K只恢复指标，不用历史OHLC补造订单、退出或1.5R激活。行情与指标恢复后清除过期入场/策略退出信号，自动等待新的实时信号。补K请求暂时失败会自动重试，已有仓位仍由收到的真实报价执行有效止损。
- 用户“手动暂停”独立保存，重连、补数据或后台重启都不会取消手动暂停；需用户点击恢复。结束中的任务和策略错误也不会被普通重连恢复开新仓；显式的“平仓并结束”指令在恢复后继续执行。
- 页面区分“行情恢复中”“手动暂停”“结束中”“异常”；日志记录补数据、自动恢复及手动操作。旧版因网络暂停的任务按完整操作日志迁移并自动恢复，最近一次用户操作为暂停的任务仍保持手动暂停。

数据库保存策略快照、完整账户账单、持仓、等待及退出激活状态、最后成交ID、指标递推状态与日志。关键交易事件与账户快照同事务提交；普通行情状态约5秒保存一次，因此异常断电可能丢失最后几秒的无交易状态。

